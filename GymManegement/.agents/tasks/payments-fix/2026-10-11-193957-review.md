# Member filter and cascading invoice dropdown for payments

The change adds a member filter dropdown to the payments table and makes the create payment modal's invoice dropdown cascade from the member selection. Newest payments now appear first. The core implementation follows the plan and existing patterns from invoices.js and members.js.

**Watch for:** Character encoding regression — the old version had mojibake Vietnamese text (`Quß║ún l├╜ Thanh To├ín`), the new version is clean UTF-8. Verify the file was saved with correct encoding. Confirm no functional regressions from the encoding fix.

**Verdict**: APPROVED

## High-level view

The member filter dropdown in the payments table toolbar lets admin filter payments by member, using client-side filtering after fetching all payments with the sortBy parameter. Sorting is applied to all API calls: `sortBy=PaymentDate&sortDir=desc` ensures newest payments render first. The create payment modal now requires member selection before showing invoices — selecting a member populates the invoice dropdown with only that member's Pending and Overdue invoices, preventing wrong-member selection. Pagination works correctly with both filters (member and payment method). All changes follow defensive accessor patterns and match the existing codebase style.

## Character encoding fix

Comparing the old and new versions, the new file uses clean UTF-8 for Vietnamese text:
- Old: `Quß║ún l├╜ Thanh To├ín` (mojibake)
- New: `Quản lý Thanh Toán` (correct)

This appears in the renderPayments() function (line 113), error messages throughout, and all user-facing strings. The change is a fix, not a regression — the old file was corrupted. The corrected encoding should be preserved by the build pipeline and render correctly in the browser.
